## 2 合并预演和明确保护范围

使用 `git merge-tree --write-tree --name-only 70d115b bba6fb3` 做非工作树合并预演，得到 **10 个文本冲突文件**：

- package-lock.json。
- src-tauri/Cargo.lock、src-tauri/src/main.rs。

lib.rs、Cargo.toml、package.json、contracts.ts 等自动合并成功也需要语义审阅，不能只处理有标记的文件。两分支端点比较中缺少 logger/settings/性能脚本/测试/交接材料，主要源于成员三基线较旧，并不意味着真实 merge 会删除这些文件；禁止按整份快照覆盖。

保护清单：成员二 note/link、真实变更 drain 与部分失败入队、草稿/日志迁移校验；成员一 Arc/Sync/cancel、锁外搜索、读池、短词和重建空间优化；成员四设置兼容、多窗口同库基准、快捷键、菜单、脱敏日志、关闭前 flush；两侧全部测试和历史证据。不得以忽略测试、提高业务超时、删除断言来消除集成失败。

## 5 具体接口与数据接线

保留 23 个顶层 command、7 个业务事件、错误码与既有 SQL 模式。成员三可选 payload/返回类型扩展是已有实现，仍需接入评审与测试。

| 接线 | 目标行为与审阅点 |
|---|---|
| DataFactory/with_data + lib.rs | 与 NoteService、Arc 索引同一 vault_id 和代次装配；私有数据不可用时保持权威文件编辑可用，错误不能伪装为“无历史” |
| export_note | preview/body 与磁盘导出含义分开；format、scope、targetPath 校验；现有 RenderedNote/ExportResult 两端一致，UI 使用已隔离预览容器 |
| note_list/read/restore | scope=versions、versionId、kind=version 不影响原草稿/回收站/重命名流程；回滚仍校验 baseHash/expectedMtimeMs，保留回滚前版本 |
| note_save 快照 | 明确旧/新内容快照目的；保存后内容哈希与 snapshot 对应。快照失败保留文件保存成功，并返回 snapshotCreated=false 与 warning，不重试覆盖正文 |
| backup_create/restore | scope=note 是单篇快照；整库包含 notes/attachments 和清单。verifyOnly 零写当前库；mode=new 不切当前库；mode=original 走维护租约、强制快照和失败回退 |
| settings | 统一 preferences、backup、vaultPath 的查询/写入规则；私有 backup 配置为其业务来源，settings.json 的遗留键保留/迁移策略有记录，不产生两个冲突来源 |
| sync 三命令与事件 | 密码只进入系统凭据端口，日志只记白名单命令/错误；sync.state/conflict.detected 使用现有传输映射；resolvedPaths 必须显式确认并复核本地/远端新鲜度 |
| 数据目录迁移 | 核对 drafts/renames/snapshots、backup-settings/schedule、sync-config/state、四张 SQL 业务状态表；外部 backups 目录和 credential_ref 逐项决定复制、引用保留或重新配置 |

成员三的 preview 更新使用 DOM editor-change 通知，需与成员四 UI 的标签/窗口/主题生命周期一起接线；该窗口通知不是新增业务事件。恢复结果、同步进度和取消要真实反映任务状态，不因为界面返回即声称后台已经安全停止。

维护租约只能控制本应用，不能阻止外部编辑器或同步盘写文件。备份/迁移需校对复制前后清单与内容哈希；检测到外部变动时失败或有界重试，原位恢复前明确外部写入边界。不能把应用互斥宣称为文件系统快照。长任务先保留现有请求/响应语义，以内部任务句柄移出全局锁；如需增加 jobId、取消载荷或新事件，必须另行记录并评审契约。
