# 版本历史重命名接线方案

2026-11-01，用户授权继续整合并以可双击启动的完整Windows软件为目标。本方案为本轮实现决定，供团队审阅，不代表其他成员已签字；不改变冻结命令、事件、错误码、SQL表或需求编号。

历史仍位于库外snapshots/<路径SHA256>，保持versionId=内容SHA256以及现有公开VersionEntry。重命名通过NoteService已有的持久renames日志串起文件改名、历史归属迁移和引用改写。App注入内部历史回调；DataService增加默认拒绝的rename_versions(from,to,journal_id,check_only)端口，LocalDataService提供真实实现，TypeScript载荷与DTO保持不变。

新重命名日志增加可选布尔historyPending。执行前校验源快照记录、正文哈希和目标目录不存在；文件成功改名后，先完成历史再改引用。历史使用同卷无覆盖目录发布，目录内.notebase-history-move标记记录本次日志ID及from/to；随后原子逐条更新JSON中的path，保留createdMs/lastUsedMs/description。中断时根据标记幂等续跑；不覆盖已有不属于本事务的目标历史，不复制混合两位笔记的历史。

historyPending=true时原路径与新路径禁止正文写入、创建复用、删除及版本回滚/快照；草稿仍可保存，重命名恢复入口仍可用。读版本前也检查，避免展示迁移到一半的JSON。历史完成并持久写入historyPending=false后，解除这两个路径的保护；引用改写尚未完成时保留成员二原有“已完成引用可继续编辑”的行为。

成功后源历史目录不再存在，在原路径新建笔记得到独立历史；链式重命名沿用同一批内容版本。目标如果残留另一笔记的历史，预检拒绝，不自动合并或删除；需先另选名称或明确处理旧历史。旧日志缺少historyPending时沿用原行为，不能凭旧日志证明历史已经迁移；已完成的历史旧重命名不做猜测式批量搬运。

新增字段兼容读取，但旧软件会忽略historyPending。回退旧版前须完成待恢复重命名，并备份snapshots和renames；否则旧版可能绕过本轮的路径保护。迁移过程保留原快照字节；损坏记录保留并报E_BACKUP_CHECKSUM，部分执行继续通过E_PARTIAL_RENAME和原journalId恢复。无覆盖目录发布的跨平台限制另行记录，不以Windows通过替代三平台验收。

本轮同时新增backup.versionRetentionDays（0–36500，默认30），Rust在backup::settings/configure验证，TypeScript在contracts.ts的BackupSettings以可选字段兼容旧响应，UI提供整数输入。旧配置缺字段只合并读取默认值，写入保留未知键；损坏结构/类型返回E_FORMAT_UNSUPPORTED且不覆盖。0关闭新记录、列表和自动清理，但保留既有文件；保存成功仍如实返回snapshotCreated=false。

每个历史目录增加私有.notebase-history-sequence文件，记录lastSequence、lastObservedMs、rollbackActive/rollbackCount；JSON版本记录增加可选sequence，公开VersionEntry不暴露。旧记录以createdMs作为排序/初始化回退；新序列从现有最大值继续，允许中断产生空号。显著回拨阈值为5秒，序列保持递增、lastUsedMs不倒退，首次进入回拨状态写白名单clock_rollback日志且不含正文。历史目录迁移包含此状态。旧版会忽略附加字段但不能保证回拨排序或可配置清理，因此降级前保留私有目录副本。

延续“私有存储不可用时保持权威文件可编辑”的既有约定：路径保护针对可读取、明确标记historyPending的事务；无权限或损坏恢复存储仍通过正常草稿/快照/恢复查询返回错误，不将无法读取的私有状态当作已安全迁移。涉及这类存储故障应先备份并修复，不能据此宣称任意损坏下的历史归属均已验收。

必测：正常/链式重命名、旧路径复用、新进程恢复、已有目标历史拒绝、元数据更新中断重试、损坏blob拒绝、historyPending期间正文拒绝且草稿保留、引用部分失败后历史仍可读。TR-04/TR-09另有配置/关闭重启用、旧配置/坏配置与模拟回拨的专项回归，不以路径迁移测试代替。
