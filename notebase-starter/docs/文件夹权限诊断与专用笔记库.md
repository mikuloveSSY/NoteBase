# 文件夹权限诊断与专用笔记库

2026-11-01，起点main c921ead。用户报告原生选择和按路径打开同一目录均得到拒绝访问（os error 5，E_IO_PERMISSION）。

## 原因与处理

通过与产品相同的FsStore只读扫描，确认所选父目录可访问，但其中一个旧测试子目录不可列出，递归扫描到该目录时失败。不是选择器的授权范围或路径格式问题。真实目录路径与诊断输出仅留本机.tools，不写入公开证据。

用户明确选择专用笔记文件夹方案，已在其指定项目目录下创建独立的空笔记子目录，并只读验证枚举成功、Markdown数量为0。原目录权限、原文件和目录位置保持不变。软件不跳过不可读目录，避免把不完整枚举当作完整笔记库。

## 变更

- FsStore打开失败补充所选目录访问阶段；递归枚举错误保留原错误码、retryable规则，加入具体库内相对位置，E_IO_PERMISSION附读取权限建议。不新增或修改公开命令、事件、错误码、SQL、数据格式。
- 新增`crates/notebase-core/examples/check_vault.rs`，仅做FsStore::open/list，输出数量或失败位置。它不读取正文、不启动App、不创建索引/私有状态、不执行回收站清理。
- Windows桌面测试只对自己新建的临时子目录拒绝ListDirectory，在finally中移除自己添加的拒绝规则；验证失败位置后恢复并重新打开、读取原文。不会对用户目录执行ACL修改。
- Windows使用说明增加专用笔记目录和权限提示说明，软件仍为0.7.0开发候选版。
