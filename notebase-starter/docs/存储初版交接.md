# 成员一存储初版交接

版本 0.2.0，2026-10-27。本版将 fs-store 的改进接入原有 application、Tauri 和 UI。仍然只有六个业务命令接通；底层 rename、delete 不等于 note_rename、note_delete、note_restore 业务已经实现。

## 内部端口

domain.rs 提供 RelPath、FileStat、WriteOutcome、StoreError 和 NoteStore。read、write_atomic、create_new、rename、delete、list、stat 七个方法均有实现；vault_path 保留作现有库管理适配。

RelPath::new 校验非空库相对路径；列表根目录使用 RelPath::root。验证采用 NFKC 视图识别兼容字符和系统保留名，但保留原始磁盘路径，避免改变已有文件身份。新建标题使用 sanitize_title 进行 NFKC 转换、非法字符替换、尾部句点空格清理及保留名前缀处理；同名依旧增加序号。

read 返回 StoredNote 原始字节及文件信息，write_atomic 接受字节并返回 WriteOutcome。这是沿用基础工程的字节保真边界，尚未与设计示例中的 NoteContent/字符串签名完全统一。后续成员二拆分 note-svc 时共同调整，不能误认为所有内部类型已最终冻结。

StoreError::AlreadyExists 用于 create_new 和 rename 的冲突判定。其余错误保留既有 AppError 信封及代码。delete 是物理删除原语，不应被普通删除业务直接调用；普通删除由成员二编排为移入 trash/。

Windows rename 使用不带 REPLACE_EXISTING 的 MoveFileExW。非 Windows 采用同文件系统硬链接后移除源名的降级：移除失败返回 E_PARTIAL_RENAME 并保留两份入口，此路径尚未实际验证。

## 现有 IPC 的明确行为

- 命令、事件、错误码名称未增加，响应字段集合保持现有定义。
- note_create 返回实际路径；UI 根据输入与实际路径差异提示文件名修正或同名避让。
- note_read 对非法 UTF-8 以替换字符展示，encoding 为 unknown、readOnly 为 true；原字节保持不变。
- 超过 10 MiB 的文件仅读取前 256 KiB，readOnly 为 true、sizeBytes 为文件大小；contentHash 为空，表示没有全文件保存凭证。UI 明示截断，后端禁止保存。
- 设计中“报 E_FILE_TOO_LARGE 同时返回内容”的信封表述存在歧义。本版用既有成功信封返回只读内容；实际保存仍返回 E_FILE_TOO_LARGE。不伪造部分内容的全文件哈希。
- 普通只读文件也返回 readOnly 为 true；保存被后端拒绝，不能依靠前端禁用按钮保证安全。
- note_save 写入无 BOM 的 UTF-8，保留原 LF/CRLF 风格；混合换行仍统一为检测到的风格。返回本次写入字节的哈希。
- note_list 按目录枚举并分页；UI 支持继续加载，不再只可访问前 500 篇。根目录 trash、attachments、.git 被排除，普通子目录同名文件夹不再被误排除。
- Tauri 异步入口改为 Result<Response,String> 满足框架约束；Ok 内仍是既有业务信封，不改变前端消费形态。

以上取舍已在本版实现和测试中记录；未宣称其他成员已评审。前端对只读、错误和文件名修正的处理属于本次存储集成所需范围。

## 需求状态与后续边界

FR-EDT-05 的名称修正、保留名与长度检查已实现；FR-EDT-10 的去 BOM、换行保留、非法编码只读已实现，应用内编码转换仍未实现。FR-EDT-09 实现有界预览，不是任意超大文件完整浏览。NFR-REL-02 有半写失败注入及 Windows 文件锁测试，但没有实际断电和物理磁盘写满验收。

仍待完成：SQLite/FTS5、检索、watcher、数据目录迁移、自动保存、草稿、恢复、链接、渲染、导出、备份、同步及设置。保存返回 indexQueued=false、snapshotCreated=false；hasAttachment 仍为 false。clientSeq 与 expectedMtimeMs 尚未参与完整状态管理。

路径保护尚不是句柄级沙箱，校验后目录更换与外部并发写入的竞态仍需强化。列表仍需遍历磁盘，IPC 仍有共享全局锁，不能宣称达到 10 万篇性能指标。NSIS 安装包、macOS/Linux 和网络盘未验收。
