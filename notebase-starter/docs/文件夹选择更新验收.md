# 原生文件夹选择更新验收

2026-11-01，起点main `bf6894fa7ab73ddcffbb2aae441f5aba6549d20c`。用户指出打开笔记库应弹出系统文件夹选择窗口，本轮补齐该交互，软件保持0.7.0开发候选版。

## 行为与接口

- 主要按钮“选择笔记库文件夹…”打开系统原生单文件夹选择，当前路径作为起始目录；选择后自动填入并进入原有打开流程。取消不调用vault_open、不清空/切换编辑会话。
- 确认选择后仍走原有flush/close和vault_open：不能用选择器绕过未保存内容、维护互斥或多窗口规则。选择器异常通过状态栏报告，原库仍可编辑；保留“按路径打开”备用入口。启动恢复直接打开已保存的库，不强制重复选择。
- 多窗口门禁用fs::canonicalize比较当前库和请求路径，兼容普通Windows路径与内部\\?\路径；同库重开仍允许，异库切换仍拒绝。路径不存在/不可读时不放行，设置迁移的多窗口限制不变；组合桌面测试保留双窗口写入冲突和异库拒绝断言。
- 使用[Tauri官方Dialog接口](https://v2.tauri.app/plugin/dialog/)，JavaScript与Rust插件均锁定2.8.4。新增桌面rfd/tauri-plugin/tauri-plugin-fs依赖，具体版本见锁文件。原生能力仅允许dialog:allow-open，未开放其他对话框或fs前端命令权限。
- 这是壳层选择交互，不增加23个业务command、7个业务事件、错误码、SQL表或schema_version。Rust在main.rs初始化插件，TypeScript在vault-dialog.ts使用directory=true、multiple=false并复用vault_open；核心存储源码与数据格式未变。

## 失败与修正

第一轮真实桌面定向检查中，插件注册/权限检查通过；新增“两个窗口用普通路径重开同库”断言得到false，见first-path-alias-failure.txt。旧门禁直接比较字符串，将普通路径与内部扩展路径误判为不同库；改为canonicalize后比较，原有异库拒绝与旧基准保护断言不变。失败时CDP关闭等待还导致夹具收尾超时，现改为先回收本测试拥有的应用PID树、再关闭CDP，未提高业务超时或删除断言；窗口关闭落盘测试仍在显式关闭与文件断言后才进入夹具收尾。

首次完整桌面20通过、1失败：历史重命名用例点击B.md后立即点击版本历史，异步导航尚未结束；实际私有快照记录的path已为B.md且说明正确。测试增加对当前路径显示B.md的明确等待，再点击版本历史，保留历史说明、读取内容和旧路径历史隔离断言；定向复验1项、随后完整21项通过。见first-full-desktop-failure.txt、history-navigation-recheck.txt、final-desktop.txt；未用延时或提高超时掩盖失败，产品二进制未因此变化。
