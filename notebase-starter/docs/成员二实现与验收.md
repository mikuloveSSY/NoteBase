# 成员二实现与验收合同

基线：367a8c1（0.3.0）。用户负责成员二 note-svc、link-svc；保持已有23个命令、7个事件和错误码名称。

## 实现范围

- 笔记新建/读/保存/软删/恢复；同名不覆盖；模板、附件。
- 自动保存：停止输入2秒内、连续输入最多10秒；草稿周期500ms；保存响应不覆盖更新输入。
- 草稿按库隔离、原子持久化；启动后显式恢复/丢弃；磁盘与草稿都变化时保留恢复副本。
- 外部变更发现/哈希再验证；冲突暂停自动保存，关闭提示不默认选择；本地/磁盘/副本三选。
- frontmatter属性、标签/父级聚合、收藏/置顶和模板；无效YAML不改写。
- 双链解析/路径与别名消歧/反链/纯文本提及/邻域图谱；重命名先预演、取消零写、持久日志与幂等续跑。

## 内部接口与兼容扩展

不新增顶层命令。现有 note_save 用可选 action 承载 draft、metadata、attachment、conflict；note_list 用 scope 承载 drafts/trash/templates 和标签/收藏过滤；note_restore 用 kind 区分草稿与回收站；未传这些字段时沿用原行为。新字段在Rust/TypeScript同步记录。未实现成员一搜索、成员三快照/同步时继续如实返回false，不伪装完成。

为避免修改成员一数据库模式，当前恢复日志持久化在库外应用数据的 renames/ JSON（与SQL rename_journal承担同一职责）。此为实现偏离，待成员一提供专用日志端口后可替换；复活条件为正式持久日志迁移接口到位。

链接业务当前从权威文件读取并在应用层计算，避免已有后台全量构建清空links后丢失关系。不得据此声称10万篇性能验收完成。复活SQLite links落地条件：成员一提供可与全量/增量索引共同更新的LinkStore端口。

新增 note_state 与 note_files 是已有 note-svc 的持久化端口适配器，不是新增业务组件；不新建SQL表。文件系统的符号链接/junction/越界保护沿用并补测。
