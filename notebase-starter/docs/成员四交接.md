## 代码入口与维护边界

- `src/main.ts`：主界面、搜索/筛选/重建/迁移、标签恢复、多窗口接入及与编辑会话协调。UI 不直接读写磁盘。
- `src/shell-ui.ts`、`preferences.ts`、`shell.css`：工作区设置、主题、布局、快捷键、命令面板及偏好校验。
- `src/bridge.ts`、`contracts.ts`：请求信封、每窗口 clientId、共享命令/事件映射；沿用成员二的扩展类型。
- `src-tauri/src/main.rs`、`shortcut.rs`、`capabilities/default.json`：23 命令分发、后台阻塞任务、窗口保护、原生菜单、Windows 全局键及最小窗口权限。
- `crates/notebase-core/src/settings.rs`、`logger.rs`：无 Tauri 依赖的设置与日志基础设施。
- `application.rs`、`lib.rs`：装配成员一索引/迁移与成员二 NoteService。业务修订仍由对应模块负责人维护。
- `scripts/verify.ps1`、`package-portable.ps1`：Windows 常规开发环境验证与便携打包，不依赖本机临时下载辅助目录。

## 共享契约与兼容性

**不变**：23 个命令名、7 个业务事件名、既有错误码、SQLite 表和 schema_version。17 个业务命令真实可用，6 个尚未实现：`export_note`、`backup_create`、`backup_restore`、`sync_configure`、`sync_now`、`sync_status`。

**集成取舍，需要团队审阅**：

1. 继续使用成员二对现有 note 命令的 action/clientId/clientSeq 等扩展，详见其交接。窗口再次打开同一库时不能重建 NoteService，否则会清空其他窗口的保存基准。失败的索引仍允许重试。
2. `settings_get` 返回 `{values}`；`settings_set {values}` 原子更新偏好。`vaultPath` 迁移必须单独提交，不能与偏好混在一个请求里。保留其他成员现存顶层键（例如 sync/backup），但不会假装实现这些键的业务。
3. 当前实现配置为顶层 `theme`/`layoutPreset`、`editor.{fontSize,lineWidth,tabSize,wordWrap}`、`keymap.{new,search,save,nextTab,commandPalette,globalQuickNote}`。与设计文档 §6.7 的示例 `appearance`、`newNote/switchNote/quickCapture/toggleFocus` **并非完全同构**；行宽单位也改为字符。Rust defaults/merged 和 TypeScript Preferences/defaultPreferences 同步维护，已测试持久化。尚无旧 appearance/keymap 格式迁移器；不要宣称完整配置契约验收通过。后续统一字段时应双向兼容读取，不能丢弃已有用户设置。
4. 新增 `notebase:shell_action` 仅用于原生菜单到当前聚焦窗口的动作通知（new/search/save/newWindow/settings/commands/focus），不是新增业务事件，不进入 EVENTS 枚举。
5. `note.changed` 在本地业务写入后发送，沿用成员一 watcher 事件。保存、删除、恢复按路径入队；重命名涉及多个文件，触发完整对账。索引失败不撤销已经成功的文件写入。
6. 设置文件格式错误时保留原件并报错；不自动用默认值覆盖坏文件。Windows 新全局键先注册，设置写入失败时尝试恢复旧键。启动时全局键注册失败当前仅记本地日志；若保存设置再次报占用，请更换全局组合。此可见性仍需完善。

## 生命周期和多人同时开发

每个窗口产生独立随机 clientId。标签缓存按窗口 label 与 vaultPath 分区，仅存合法相对路径和活动标签；最多恢复 100 个。关闭、切换笔记/标签、切库等先调用成员二会话 flush；冲突未处理时保留窗口/笔记。多窗口共享一个 App 与一个当前库，当前不支持每窗口不同库。

已有其他窗口时，外壳拒绝切换/迁移（E_CANCELLED），同库 reopen 允许。双窗口编辑同一文件，旧基准写入被拒绝；用户显式选择保留本地、使用磁盘或另存副本。UI 不因收到列表/索引事件重建编辑器而丢光标。

队友继续提交时，先 `git fetch origin`，记录 main 与各功能分支 SHA；在独立集成分支合并差异，再跑受影响测试。不要对正在开发的工作区盲目 `git pull`，也不要覆盖旧文件重新解压 ZIP。合并本分支前重点审阅共享配置差异和 application/main 的语义整合。
