# 0.3.0 索引基础交接

2026-10-27。本版完成 SQLite 索引基础与打开库时的后台构建，未实现 SearchService、watcher 或增量索引队列。不得将底层 trigram 测试当作完整搜索功能验收。

## 目录与端口

- `crates/notebase-core/src/index/schema.sql`：从设计 §6.4 提取的 10 张逻辑表及既定索引。FTS5 自动生成的影子表不算新增业务表。
- `index/sqlite.rs`：SqliteIndexStore，一个写连接、两个轮换使用的只读连接；WAL、foreign_keys=ON、synchronous=NORMAL、busy_timeout=5000ms、每连接 64 MiB 页缓存上限。writer.lock 文件的操作系统锁限制同库写会话，崩溃后锁由系统释放，锁文件本身保留。
- `index/mod.rs`：NoteRecord、IndexStatus、IndexProgress、IndexStore 与 IndexSession。应用层通过 IndexSession 获取状态/标记过期/请求重新扫描；后台线程不持有 App 的全局锁。
- `index/worker.rs`：专用写线程，接收容量 1 的合并刷新请求。这里不是按路径去重的 IndexQueue，保存响应仍为 indexQueued=false。
- `index/extract.rs`：共用 comrak 配置和正文抽取入口，供成员三后续 renderer 复用；未交付 HTML 渲染业务。

IndexStore 本版实现 upsert_batch、remove、get、status；设计中的 search、backlinks、rename_references 和异步 rebuild 仍待对应版本接入。get 是给后续服务/测试使用的单篇读取，不新增 IPC 命令。

## 持久化与一致性

默认位置为 Tauri app_data_dir 下的 `vaults/<vault_id>/index.db`。Windows 通常为 `%APPDATA%/edu.notebase.desktop/vaults/<vault_id>/index.db`。库标识沿用 0.2.0 的规范绝对路径 SHA-256 前 16 位；相对路径保留原磁盘身份，不为符合原 SQL 的 NFC 注释而改名。

开发/测试可设置绝对路径环境变量 NOTEBASE_DATA_DIR。后台先检查真实父目录，再创建缓存；拒绝放入当前笔记库，拒绝 vaults 和库 ID 目录经过符号链接/junction。UI/测试都不能绕过这一检查。它不是用户数据目录迁移功能，也不提供完整句柄级路径沙箱。

notes 只存元数据，note_fts 为普通、自带内容的 FTS5 trigram 表；不是 external-content/contentless，未改为 unicode61。FTS 的 rowid 与 notes 的 SQLite rowid 配对，以免每次更新扫描 UNINDEXED path 列；业务身份仍是路径。每个 upsert_batch 事务同时写 notes、FTS、aliases、tags；失败整体回滚。更新不使用 INSERT OR REPLACE，避免破坏已有外键。remove 同事务删除 notes/FTS，更新链接的 resolved/ambiguous，外键清空目标并清理源关联。

每批最多 200 篇，累计输入达到 8 MiB 时提前提交；单篇仍受 10 MiB 上限约束。初始清理与各批提交是独立事务，中途失败会留下部分索引并标记 offline。当前没有旧索引原子切换或“重建中仍可检索”保证，这属于 0.6.0。重建只清理 notes、FTS、aliases、tags、links；不清理 snapshot_index、sync_state、sync_tombstone、rename_journal。

schema_version=1，tokenizer_version=trigram-comrak-1。每次打开库都会扫描并刷新，以覆盖尚无 watcher 时的外部变化。版本值不匹配且实际模式仍与本版完全一致时，只重建上述派生表并更新版本；四张业务状态表保留。未知表/索引/触发器结构、身份不匹配或数据库损坏时停止索引并保留数据库，不擅自删除。跨真实模式版本的迁移与损坏恢复仍待 0.6.0，不能宣称完整 BR-05 已完成。

## 抽取规则与共享决策

读取容忍 BOM，索引哈希为原字节 SHA-256 的 64 位 hex（IPC 的 sha256: 前缀不写入数据库）。合法 frontmatter 提取 title/tags/aliases，created/updated 按带时区的 RFC3339 转 UTC 毫秒；无效时间留 NULL。合法 frontmatter 从索引正文排除；YAML 解析失败时整篇当正文，不改源文件。

comrak 开启 table/tasklist/strikethrough/autolink，关闭 footnotes/description_lists/superscript，保持安全 HTML 渲染选项。0.57 已移除 tagfilter 开关（见 [comrak 变更记录](https://github.com/kivikakk/comrak/blob/0.57.0/CHANGELOG.md)）；因此不声称实现原设计的五个扩展开关，本版不采集 HTML 节点，也未实现预览/导出。成员三接 renderer 时应明确安全 HTML 策略。本次是实现决策记录，不代表其他成员已评审。

正文保留文本、代码块/行内代码、图片替代文字，去掉 Markdown 格式标记并保留段落分隔。has_attachment 根据 Markdown 链接/图片的 attachments/ 或 ../attachments/ 前缀提取，尚不覆盖所有附件引用形式；现有 note_list 的 hasAttachment 仍按原接口为 false，后续应统一接索引读取。链接表结构已建立，链接解析/消歧业务仍由成员二负责。

非法 UTF-8、超过 10 MiB 或扫描后消失的文件跳过，不建立替换字符或截断正文的假索引。只要有跳过项，状态即 offline，并发 error.raised 说明 skipped 数；可正常索引的笔记已提交，但不能称为完整库索引。只读但合法的小文件可以正常索引。

## IPC、事件与生命周期

新增接通既有 index_status，共 7 个命令实际接通、16 个未实现；23 个名称与现有字段不变。vault_info.indexState 现在返回真实会话状态。

```json
{"state":"ready","noteCount":205,"indexBytes":250000,"lastFullBuildMs":1793059200000,"progress":null}
```

以上是字段示例，不是性能数据。indexBytes 是最近状态快照时 DB+WAL+SHM 文件大小之和。构建中 progress 为 `{phase,done,total,elapsedMs}`，done 是处理条目数，noteCount 是已提交的有效记录数。空库也能完成构建。

后台通过 Tauri 发出既有 index.state、index.progress、error.raised；事件接收函数应短小且不可同步回调会话。UI 每秒读 index_status 显示状态，不订阅其余业务事件。切库取消旧会话并禁止其继续发事件；旧任务可能在当前枚举/单篇读取完成后才退出，但始终只访问原库。重新打开同库复用写会话；初始化失败时会重新尝试创建会话。

本地新建/保存会标记索引过期；构建期间发生保存也不能将这一轮标为 ready。重新打开当前库触发刷新。尚无 watcher，外部编辑不会立即改变状态，ready 仅指最近扫描完成，不代表持续同步。文件保存/读取不因索引不可用而失败。
