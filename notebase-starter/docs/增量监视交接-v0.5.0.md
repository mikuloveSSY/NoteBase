# 0.5.0 增量与监视交接

日期：2026-10-29。成员一交付。当前支持保存后的索引排队、原生文件事件、周期对账和桌面文件列表通知；数据目录迁移、损坏恢复及手动重建仍在 0.6.0。

## 队列与单写者

`index/queue.rs` 的 IndexQueue 最多缓存 4096 个不同路径，同一路径合并，以本地来源优先。默认安静 150 ms 后处理，连续事件最多等待 500 ms；唤醒通道容量为 1，重复唤醒不积压。超限时清空待处理路径并设置全库对账标志，后台发 error.raised 告知溢出，不把溢出当作处理成功或静默丢弃。

`index/incremental.rs` 与现有 worker 共用唯一写连接。普通任务只查询涉及路径的旧指纹，读取当前真实文件，按原字节 hash、mtime 和 size 判定更新；不依赖事件顺序猜测文件最终状态。每批最多 200 篇，累计输入达到 8 MiB 提前提交。notes/FTS/aliases/tags 的更新保持现有同事务契约；删除同时更新链接目标状态。同批更新与删除可以分成两个事务，处理期间搜索暂不可服务，不提供整个文件系统事件的原子快照。

新建和保存先成功写文件，再 enqueue。note_save 的现有 indexQueued 字段现在表示任务被活跃会话接收，不表示索引已经完成；未接收返回 false 并附警告，文件保存仍成功。snapshotCreated 仍为 false。相同内容的 watcher 回声不重复发 note.changed；正常队列保留本地来源，避免给本窗口保存重复通知。队列溢出后全库对账可能无法保留全部路径来源，消费者仍需按路径/hash 合并通知。

增量完成会更新 meta.index_revision，使旧搜索游标失效；没有新增表/列或改变 schema_version。搜索计数、结果和游标仍在只读事务中；会话未追平时明确 E_INDEX_UNAVAILABLE。自动索引不是自动保存：编辑器中的未保存文本仍须手动保存。

## 监视与对账

`index/watcher.rs` 使用 notify 8.2.1 的 RecommendedWatcher，Windows 使用原生文件通知。回调只处理路径/事件并入队，不读文件、不写数据库。覆盖文件新建/修改/删除、双方重命名路径、编辑器临时文件原子替换；目录重命名或不明确的目录变化安排全库对账。访问事件和库根 trash/attachments/.git 排除，路径读取继续受 FsStore 防越界和 junction 检查保护。

启动时先安装 watcher 再扫描；首次构建后再对账，补上扫描期间变化。运行期间默认每 300 秒对账，比较真实文件与索引指纹并补更新/删除；内容 hash 可识别 mtime 相同的变化。原生监听初始化失败或回调报错时，通过 error.raised 告知并降级为同周期轮询；事件 rescan 标志和队列溢出也立即安排对账。WorkerOptions 可配置原生监听开关、周期、防抖和容量，尚无设置界面。

监听失败后本会话不会反复重启原生后端，仍依靠周期对账；切换库重新建立监听。普通处理 I/O 错误会将索引设为 offline 并安排后续对账重试。非法 UTF-8、超大文件和不安全路径不保留旧的可搜索命中，索引保持 offline；文件修复后可通过事件或对账恢复。损坏数据库本身仍保留原件并拒绝自动删除。

切库/关闭发送取消信号，旧会话不再发事件、也不写新库。取消检查在文件之间，已开始的枚举/单篇读取可能继续至结束；没有在 App 全局锁内 join 整个扫描。普通增量任务不做 FTS optimize。备份恢复期间的暂停接口尚待与成员三的业务集成。

## Tauri 事件传输适配

本轮桌面测试发现 Tauri 不允许事件传输名带点号，原有 name 直接 emit/listen 会失败。保留七个冻结的逻辑事件名，增加显式传输适配：Rust domain::transport_event_name 与 TypeScript transportEventName 同步映射，前后端均有测试。此兼容调整需要其他消费者采用同一映射，尚未经过其他成员评审。

| 逻辑名 | Tauri 传输名 |
|---|---|
| note.changed | notebase:note_changed |
| note.conflict | notebase:note_conflict |
| index.progress | notebase:index_progress |
| index.state | notebase:index_state |
| sync.state | notebase:sync_state |
| conflict.detected | notebase:conflict_detected |
| error.raised | notebase:error_raised |

本版实际产生 note.changed、index.state、index.progress 和 error.raised，其余只是保留契约。note.changed 的 external 来源在索引提交后发送，删除/移除索引时 contentHash 为空字符串，通知消费者重新查询，不能当作合法文件哈希。UI 收到外部变化后刷新文件列表；活动笔记只提示磁盘变化，保留未保存文本，保存前继续进行原有冲突检查。IPC 命令仍为 8 个接通、15 个未实现。

## 验证与边界

本机 Windows x64、Rust 1.99.1 MSVC、Node 24.16、WebView2。Rust 测试 56 项、前端契约 3 项；新增覆盖有界队列/去重/溢出、原生文件与目录重命名、原子替换、轮询漏事件补偿、rescan 注入、非法文件修复、增量游标过期及事件映射。Windows 小库测试新建到搜索可见实测 201–203 ms，并断言小于 1 秒；强制轮询测试将周期缩短至 100 ms，不能用它证明默认 300 秒轮询也有 1 秒时延。

浏览器 6 项、真实桌面 8 项回归全部通过，桌面覆盖保存后不重开库直接检索、外部新文件自动进入列表/检索、外部改写保留未保存编辑。曾发现列表不刷新，经诊断为点号事件被 Tauri 拒绝；增加映射后该用例通过。全套共 73 项测试通过。Clippy -D warnings、前端和 Windows release 构建通过（约 627 kB 主包体积提示仍存在）。

未完成十万/二十万篇性能与端到端尾延迟统计、实际 OS 监听资源耗尽、网络盘、macOS/Linux、物理写满/断电和 NSIS 安装包验收。搜索仍经 App 串行派发且每次单独打开只读连接，0.4.0 的并发/连接池和大库分页优化尚未解决；不将本版视为整套需求验收完成。
