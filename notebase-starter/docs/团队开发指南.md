# 团队开发指南

当前以 [成员一交接总览 v0.7.0](成员一交接总览-v0.7.0.md) 为统一入口；下列开发顺序保留分工思路，具体完成范围以根目录 CHANGELOG 和最新版交接为准。

## 目录与职责

| 路径 | 职责与维护人 |
|---|---|
| `src/contracts.ts` | 共享命令、响应与错误类型；四人协商，成员四整合 |
| `src/bridge.ts` | 界面到桌面核心的 IPC 适配；成员四 |
| `src/demo.ts` | 浏览器内存联调数据；成员四；不可视为后端实现 |
| `src/main.ts`、`src/style.css` | 基础界面；成员四 |
| `src/shell-ui.ts`、`src/preferences.ts`、`src/shell.css` | 设置、快捷键、命令面板、布局；成员四 |
| `crates/notebase-core/src/settings.rs`、`logger.rs` | 偏好持久化与脱敏日志；成员四 |
| `src-tauri/` | app-shell、依赖装配、原生命令入口及桌面配置；成员四 |
| `crates/notebase-core/src/domain.rs` | 无 I/O 的值对象、规则和端口；按领域归属维护 |
| `crates/notebase-core/src/application.rs` | 成员一/二服务与设置的统一编排；成员四维护集成，业务变化与所属成员核对 |
| `note_service.rs`、`links.rs`、`note_state.rs`、`src/editor-session.ts` | 笔记、链接、恢复及前端会话；成员二 |
| `crates/notebase-core/src/infra.rs` | 当前 fs-store 文件适配器；成员一 |
| `crates/notebase-core/src/index/` | SQLite 模式、存储端口、后台构建；成员一。extract.rs 的 comrak 配置供成员三共用 |
| `crates/notebase-core/tests/` | 真实临时目录的核心集成测试；模块负责人各自补充 |

`notebase-core` 是编译与测试用的 crate，不是新增业务组件。它不依赖 Tauri，因此缺少桌面环境时仍可测试业务核心。Tauri 文件操作被派发到后台任务；基础版通过一个共享锁串行处理核心操作，后续由 index-worker 等组件细化线程模型。

## 全部组件的责任人

- 成员一：fs-store、index-store、index-worker、watcher、search-svc。
- 成员二：note-svc、link-svc。
- 成员三：renderer、pdf-exporter、export-svc、backup-svc、sync-svc、webdav-sync、keychain-store。
- 成员四：ui、app-shell、logger。

尚未实现的组件只在任务归属中列出，没有用空壳模拟完成。后续沿用原有名称，在 Rust 核心的应用层或基础设施层分别落地。

## 开发顺序

1. 本分支已合并 main `c84f8a8` 与成员二 `7ff1277`，保留双亲历史；详情见 [成员四交接](成员四交接.md)。读取分支以具体 SHA 为准，不能把文档中的未来计划当作已交付代码。
2. 一继续检索并发/性能与存储边界，二继续 note/link 业务，四维护 UI/外壳/集成。共享文件冲突应合并语义，不整文件选一方覆盖。
3. 三先交 renderer 和导出，再交备份/快照、同步；四接收后补相应 UI 和失败流程测试。
4. 最终共同验收三平台、规模性能、安装卸载与恢复。同步仍在原范围内，未因后置而删除。

## 必须保持的边界

- UI 只通过 IPC 访问业务，不直接读写磁盘或 SQLite。
- 应用层只调用领域规则和端口；具体基础设施在装配入口注入。
- 文件是权威数据源。索引是派生缓存，只能放应用数据目录；索引丢失可重建。
- note_fts 的表形态和短查询回退沿用原设计。不得以 unicode61 替代中文检索，也不得把两字查询直接交给 trigram。
- 保存成功不等于索引或快照已完成，响应状态必须如实返回。
- 成员一统一维护数据库结构，其他成员通过端口使用。
- renderer 由成员三统一实现，预览、导出和索引共用 comrak；界面暂不引入第二个解析器。
- 每个模块负责人提交测试和需求完成清单。成员四组织联调，问题由所属负责人修复。

## 已知待完善项

0.3.0 索引写入与首次构建已完成，0.5.0 已实现按路径去重的 IndexQueue 与 watcher；0.6.0 已交付后台重建与 vaultPath 迁移，0.7.0 接入搜索锁外执行和读连接池，性能以本版实测报告为准。模式、共享解析选项和生命周期约定见 [索引基础交接](索引基础交接.md)。不要将单次扫描完成视为文件变化后的实时索引保证。

成员二已引入 clientId/clientSeq、草稿、保存基准和显式冲突处理；同库多个窗口复用服务但隔离客户端基准。当前仍使用原始字节存储端口，接口取舍见 [成员二交接](成员二交接.md)。全局 App 锁、大库枚举和快照联调仍待改进。

路径检查已拒绝符号链接和越界路径，但并未采用操作系统句柄级沙箱。外部程序在校验与写入之间更换目录或同时写入的竞态仍需完善；测试覆盖的是保存前已经发生的外部修改。

混合换行会按文件检测结果统一为 LF 或 CRLF。成员二附件与恢复业务已集成；真实物理断电/磁盘写满、安装卸载、跨平台和规模性能没有完成验收。当前证据见 [成员四验证记录](成员四验证记录.md)，旧文档中的“尚未实现”与旧测试数字仅代表对应历史版本。
