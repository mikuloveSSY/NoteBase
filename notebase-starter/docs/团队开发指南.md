# 团队开发指南

## 目录与职责

| 路径 | 职责与维护人 |
|---|---|
| `src/contracts.ts` | 共享命令、响应与错误类型；四人协商，成员四整合 |
| `src/bridge.ts` | 界面到桌面核心的 IPC 适配；成员四 |
| `src/demo.ts` | 浏览器内存联调数据；成员四；不可视为后端实现 |
| `src/main.ts`、`src/style.css` | 基础界面；成员四 |
| `src-tauri/` | app-shell、依赖装配、原生命令入口及桌面配置；成员四 |
| `crates/notebase-core/src/domain.rs` | 无 I/O 的值对象、规则和端口；按领域归属维护 |
| `crates/notebase-core/src/application.rs` | 当前笔记用例编排；成员二，后续按原组件拆分服务 |
| `crates/notebase-core/src/infra.rs` | 当前 fs-store 文件适配器；成员一 |
| `crates/notebase-core/src/index/` | SQLite 模式、存储端口、后台构建；成员一。extract.rs 的 comrak 配置供成员三共用 |
| `crates/notebase-core/tests/` | 真实临时目录的核心集成测试；模块负责人各自补充 |

`notebase-core` 是编译与测试用的 crate，不是新增业务组件。它不依赖 Tauri，因此缺少桌面环境时仍可测试业务核心。Tauri 文件操作被派发到后台任务；基础版通过一个共享锁串行处理核心操作，后续由 index-worker 等组件细化线程模型。

## 全部组件的责任人

- 成员一：fs-store、index-store、index-worker、watcher、search-svc。
- 成员二：note-svc、link-svc。
- 成员三：renderer、pdf-exporter、export-svc、backup-svc、sync-svc、webdav-sync、keychain-store。
- 成员四：ui、app-shell、logger。

尚未实现的组件只在任务归属中列出，没有用空壳模拟完成。后续沿用原有名称，在 Rust 核心的应用层或基础设施层分别落地。

## 开发顺序

1. **共同起点**：0.3.0 已在 Windows 验证桌面读写及库外后台索引；成员一、二继续审查存储和保存行为，成员四负责后续整体验收。
2. **第一轮并行**：一推进检索服务与增量索引；二补草稿及恢复；三接 comrak 渲染和导出准备；四保持界面闭环并接状态事件。
3. **第二轮集成**：接增量索引与检索、链接和重命名、版本快照与备份，逐项进行故障测试。
4. **最后收尾**：兼容性、性能、安装包、操作说明。同步按原范围弹性安排后置，不自动从需求清单删去。

## 必须保持的边界

- UI 只通过 IPC 访问业务，不直接读写磁盘或 SQLite。
- 应用层只调用领域规则和端口；具体基础设施在装配入口注入。
- 文件是权威数据源。索引是派生缓存，只能放应用数据目录；索引丢失可重建。
- note_fts 的表形态和短查询回退沿用原设计。不得以 unicode61 替代中文检索，也不得把两字查询直接交给 trigram。
- 保存成功不等于索引或快照已完成，响应状态必须如实返回。
- 成员一统一维护数据库结构，其他成员通过端口使用。
- renderer 由成员三统一实现，预览、导出和索引共用 comrak；界面暂不引入第二个解析器。
- 每个模块负责人提交测试和需求完成清单。成员四组织联调，问题由所属负责人修复。

## 接口状态

当前接通17个既有命令：vault_open、vault_info、note_list、note_create、note_read、note_save、index_status、search、index_rebuild、settings_get、settings_set（仅vaultPath），以及note_delete、note_restore、note_rename、link_backlinks、link_mentions、link_graph。其余6个为导出、备份和同步相关占位命令。

保持原命令、逻辑事件、错误码和SQL表；可选action/scope/kind扩展见[成员二交接](成员二交接.md)。真实文件变动已进入IndexQueue，indexQueued按实际接收返回；snapshotCreated继续false。note.changed/note.conflict和索引/错误事件在Tauri两端统一使用transportEventName映射；UI兼容监听刷新与哈希检查。

## 已知待完善项

0.3.0 索引写入与首次构建已完成，0.5.0 已实现按路径去重的 IndexQueue 与 watcher；0.6.0 已交付后台重建与 vaultPath 迁移，检索性能优化仍待完成。模式、共享解析选项和生命周期约定见 [索引基础交接](索引基础交接.md)。不要将单次扫描完成视为文件变化后的实时索引保证。

本工程不是实现契约的最终完成版：0.2.0 已增加 RelPath、FileStat、WriteOutcome、StoreError 和七个存储方法，仍使用原始字节读写签名，详见 [存储初版交接](存储初版交接.md)。成员二已加入clientId隔离的哈希/序号与expectedMtimeMs检查、草稿恢复和三选冲突交互；原生全库watcher已由成员一接入；多窗口布局仍由成员四完成。

路径检查已拒绝符号链接和越界路径，但并未采用操作系统句柄级沙箱。外部程序在校验与写入之间更换目录或同时写入的竞态仍需完善；测试覆盖的是保存前已经发生的外部修改。

混合换行会按文件检测结果统一为 LF 或 CRLF。成员二列表根据笔记相对附件引用显示hasAttachment。0.2.0 已验证有界大文件只读预览、半写失败注入及 Windows 文件锁；实际断电、磁盘写满、恢复和安装包尚未验收。具体证据见 [本版验证记录](验证记录-v0.3.0.md)。
