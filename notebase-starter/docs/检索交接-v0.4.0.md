# 0.4.0 检索交接与验证

日期：2026-10-29。本版接通既有 search 命令，命令名、事件、数据库模式和错误码保持既有定义；8 个命令实际接通、15 个仍未实现。全文检索使用库外索引，文件仍为权威数据源。

## 查询契约

Rust SearchQuery/Filters 位于 index/search.rs，TypeScript SearchQuery/SearchPage 位于 src/contracts.ts。query 必填；sort 为 relevance（默认）或 mtime；limit 默认 50，范围 1–200；cursor 为不透明字符串或 null。不支持的字段/排序会明确拒绝。

支持双引号短语、空白分隔的 AND 查询、减号排除、tag:/path:/title: 字段。未知字段报 E_QUERY_UNSUPPORTED，空查询、空字段值、未闭合引号和无效游标报 E_QUERY_SYNTAX。查询限 1024 字符、32 个词。没有 OR、括号或反斜杠引号转义语法。

filters 支持 tags（全部标签精确匹配）、pathPrefix（字面目录前缀）、mtimeFromMs/mtimeToMs、hasAttachment。补齐创建时间过滤的共享字段 createdFromMs/createdToMs，均为含端点的 UTC Unix 毫秒；无 created 值的笔记不满足创建时间范围。新增创建时间字段是对设计请求示例缺口的明确扩展，Rust/TypeScript 同步定义，尚未经其他成员评审。前端提供查询语法输入框，结构化过滤可通过 IPC 使用。

至少三个 Unicode 字符的普通词走 FTS5 trigram，同时匹配标题、别名和标签；一至两字词走标题/别名/标签及 note_fts_content.c2 的 LIKE 扫描。LIKE 的 %、_、反斜杠按字面转义。短查询返回 degraded=true、degradeReason=short-query-scan，不冒充零结果。FTS 查询对输入加双引号并转义，SQL 值始终绑定参数。

relevance 使用标题 10、别名 6、标签 4、其余 1 的词匹配权重求和；不是 BM25。其次按修改时间降序、路径升序稳定排序。mtime 直接按修改时间/路径排序。总数为当前快照的精确计数，沿用 totalApprox 字段。游标绑定查询、过滤、排序、limit 和完整构建时间；查询或索引改变后需从第一页重查。当前使用 OFFSET，不宣称大库分页性能达标。

片段从正文首次命中附近截取最多 160 个 Unicode 字符，转义原文 HTML 后仅插入受控 b 标签。界面使用 textContent 展示标题/路径，不直接注入片段 HTML；点击结果走原 note_read。matchedIn 说明命中的标题、别名、标签或正文来源。

## 生命周期与限制

search-svc 的解析、路由、排序、片段目前统一位于独立 search 模块；IndexStore 暴露 search 端口。桌面 IndexSession 为每次查询打开独立只读连接，使用 SQLite 读事务保证计数和结果处于同一快照；尚未复用后台线程持有的两条读连接。

会话不为 ready（包括本地保存后过期）时返回 E_INDEX_UNAVAILABLE；查询期间会话代次变化也拒绝结果。重新打开库刷新后可再搜索。现阶段仍通过 App 串行派发搜索，会影响并行编辑响应；移出该锁、读连接池复用和大库性能优化仍待完成。外部变更尚无 watcher 自动追踪。

尚未完成增量队列、watcher、后台手动重建/迁移、完整链接业务，也未验收十万篇性能、100 标记词大语料、三平台、网络盘或安装包。本版为可用的检索初版，不将上述边界标记为已完成需求。
