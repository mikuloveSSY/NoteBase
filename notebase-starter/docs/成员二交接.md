# 成员二交接：笔记编辑与知识组织

本分支 feat/member2-notes-links 基于367a8c1，软件版本仍0.3.0；未发布新版本。新增功能由真实服务与对应界面消费，不以浏览器内存演示冒充磁盘持久化。

## 文件与职责

| 文件 | 职责 |
|---|---|
| core/src/note_service.rs | note-svc用例与保存/恢复/冲突/重命名编排 |
| core/src/links.rs | 无I/O链接解析、消歧、改写计划、反链/提及/图数据 |
| core/src/organization.rs | 无I/O frontmatter检查与更新、父标签匹配、模板 |
| core/src/note_state.rs | 库外草稿/恢复日志端口及JSON原子持久化 |
| core/src/note_files.rs | 受保护目录准备、无覆盖原子创建、回收站发现、附件写入 |
| core/src/application.rs、lib.rs | 保留App外部入口，装配note-svc和已存在索引会话 |
| src/editor-session.ts | 可测试的自动保存、草稿、外部检查和revision状态机 |
| src/main.ts、bridge.ts、contracts.ts | 最小业务面板接入与共享类型；整体UI仍由成员四维护 |

表中core即crates/notebase-core。FsStore、数据库模式和索引工作线程未改动。new_local_app采用显式内存私有状态用于测试；桌面new_indexed_app采用库外持久状态。独立嵌入调用如需恢复，使用new_stateful_app(data_root)。

## 既有命令的兼容扩展

保留23个命令/7个事件/23个错误码。Rust领域仍沿用AppError信封。bridge每窗口创建clientId，所有note操作带相同clientId，信封与payload携带clientSeq。

| 入口 | 新增可选请求 | 返回/语义 |
|---|---|---|
| note_save | action:draft + path/body/baseHash | 原文件零写；确认草稿已原子落盘 |
| note_save | action:metadata + updates对象 | null移除字段；未知字段和正文保留；坏YAML拒绝 |
| note_save | action:attachment + name/bytes/image/directory? | 保存相对附件并返回markdown，由界面插入后正常保存 |
| note_save | action:conflict + choice:local/disk/copy + diskHash/body | 用户显式处理；再次检查diskHash，防二次外改 |
| note_read | probe:true | 查看当前磁盘版本，不刷新客户端保存基准 |
| note_list | scope:drafts/trash/templates/renames | 返回真实恢复/回收/模板/待续跑数据 |
| note_list | tag、favorite、dirPrefix、cursor、limit | 父标签包含后代；保留路径分页 |
| note_create | body、templatePath、dir | 一次原子无覆盖创建；模板支持三占位符 |
| note_restore | kind:draft + draftId + choice:restore/copy/discard | 基准变化自动恢复副本，绝不覆盖外部版本 |
| note_restore | trashPath | 原路径冲突时加(2)等后缀 |
| note_delete | permanent:true + confirmed:true | 永久删除需显式确认；默认移到trash |
| note_rename | planOnly:true | 仅预演，无文件/恢复日志写入；返回plan.id |
| note_rename | planOnly:false + planId | 哈希验证预演新鲜度后执行，按日志可续跑 |
| note_rename | resumeId | 校验已有恢复记录与每文件哈希后继续，幂等 |
| link_backlinks | resolveTarget | 返回同名候选及歧义标志，用于链接跳转 |

命令未提供扩展字段时保留普通行为；一个有意修正是BR-02重名序号从(2)开始，旧版(1)fixture已同步。每次保存先写权威文件，再标记索引过期；当前尚无增量队列与快照，indexQueued/snapshotCreated保持false并在warnings说明。

## 数据安全与实现取舍

保存按客户端身份、基准哈希、序号和可选mtime判断。周期probe不会悄悄接受磁盘版本。冲突对话框无默认选择，关闭仍暂停，进一步输入继续存草稿。异步保存期间允许输入，旧响应仅确认提交的revision，不把更新内容误标已保存。

草稿每500ms调度（连续输入也触发），停止输入2s、连续输入10s调度保存；系统负载和I/O时延仍影响实际落盘完成时间。正常关闭/切换flush，发生冲突或错误时保留当前内容。浏览器卸载无法保证await，依靠草稿和原生关闭保护。

草稿与重命名日志位于app_data/vaults/<vault_id>/drafts和renames，JSON原子替换、64MiB单记录限制，符号链接/junction拒绝，坏/超限记录读写删均拒绝且保留。回收站在库内trash，按文件名删除时刻在开库时清理30天过期项；无法识别的手工文件不自动删。附件上传单次32MiB、默认附件目录20GiB预算；自定义同目录附件总量的完整统计仍需成员一提供统一资产枚举接口。

与设计的两个明确偏离：rename_journal暂用库外JSON恢复日志替代SQL表；链接关系当前从权威文件计算，暂不写成员一会被全量构建清空的links表。复活条件分别是成员一提供正式日志迁移端口、可同时服务全量/增量的LinkStore端口。没有改变现有SQL模式或伪造索引性能。

桌面入口新增create:false后在setup显式构建同一个配置窗口，尊重WEBVIEW2_USER_DATA_FOLDER，解决Tauri默认WebView目录在测试隔离参数生效前触发访问拒绝。主窗口增加core:window:allow-close和allow-destroy，后者由Tauri onCloseRequested在用户处理结束后内部调用，用于flush后正常关闭。没有关闭WebView沙箱或TLS验证。

## 本地演示

从notebase-starter目录在已启用Rust/MSVC环境运行npm run desktop；本工作区独立Rust环境可用 bash ../../.notebase-tools/rust/with-rust.sh npm run desktop。测试与构建使用该启动器可同时复用专用TEMP。打开临时库后：

1. 新建笔记、持续输入并观察自动保存；切换标签页后重新打开。
2. 属性面板填写title/status/tags/aliases和收藏；查看文件frontmatter。
3. 创建templates/每日记录.md，用{{title}}/{{date}}/{{time}}，选择模板新建。
4. 插入[[目标]]，在链接面板跳转/消歧，查看反链及提及转换；加载图谱。
5. 重命名先查看清单再取消或确认；恢复面板可继续未完成任务。
6. 外部编辑同一文件，观察三种冲突处理；关闭弹窗保持暂停。
7. 删除到回收站并恢复；恢复遇同名文件不会覆盖。

具体测试命令、实际通过数和未验证指标见[成员二验证记录](成员二验证记录.md)。
