## 已整合的功能

成员三的 DataFactory/DataService 已与当前库和私有状态装配：安全 Markdown 预览，MD/HTML/PDF/整库 ZIP 导出，保存前后版本快照、手动快照、历史查看/回滚，备份校验、新位置及原位恢复，定时维护，WebDAV 和系统凭据。PDF 保持 Windows Chrome/Edge 适配；非支持平台明确报错。

编辑器保留自动保存、草稿和外改冲突保护。保存成功、索引入队、快照持久化分别报告；快照失败不回滚已成功的文件保存。快照再次读取的内容哈希必须等于本次保存结果，防止把外部更新误记为本次保存。损坏的历史 blob/记录保留并报错，不伪装快照成功。

预览仍为 sandbox iframe，使用共用 comrak 和链接规则；旧预览被 UI revision 和库代次拒绝。整库导出不能伪装成只读 preview 请求。成员四主题、标签、窗口及脱敏日志继续独立维护。

## 本轮内部接口决定

以下为用户授权下的集成实现决定，供团队 PR 评审，不代表其他成员已逐项签字同意。23 个顶层 command、7 个业务事件、错误码、SQL 表和 schema_version 不变。

| 范围 | 最终行为 | 定义与验证位置 |
|---|---|---|
| 索引暂停 | IndexSession::suspend(&self)；先取消，等待查询生命周期锁，再 join 写线程，停用时状态为 unavailable。未知实现默认返回错误，不能假装暂停 | index/mod.rs、index/worker.rs；恢复及 team_all 组合测试 |
| 长任务 | App::begin_data_task → DataTask::run → App::finish_data_task；请求/响应语义保持同步，耗时操作在 App Mutex 外，IPC 等待方取消也不丢弃 worker 的收尾 | application/tasks.rs、Tauri execute_data_task；阻塞任务下 App.try_lock 测试 |
| 维护互斥 | 长备份、导出、恢复、同步期间拒绝新文件写入、设置/切库和重叠任务；笔记读取和草稿可用。同步返回 E_SYNC_BUSY，其余维护用 E_CANCELLED 并可重试；自动保存保留文本、草稿并按 1 秒限速重试 | application.rs、editor-session.ts 与状态机测试；没有新增 DTO 字段 |
| 协作取消 | 内部 DataService::set_cancel_flag；原生关闭/退出请求设置标志，完成或失败收尾前仍保留窗口/任务租约。同步在文件间及网络请求后检查，单个网络请求仍受 30 秒超时约束；恢复目录发布/回退阶段不打断 | data_services、application/tasks.rs、Tauri 关闭/退出回调；取消后租约保留测试 |
| 原位恢复 | 多窗口时先拒绝真实恢复；单窗口 UI 先 flush/close 旧编辑会话，再执行恢复。索引安全停止，完成后重新装配笔记服务、重建索引并增加库代次，禁止旧文本再次写回 | member3.ts、main.ts、tasks.rs；真实桌面原位恢复与多窗口拒绝用例 |
| 同步部分失败 | 无论成功、错误或取消，收尾均安排索引对账和外部变化核对；后台未配置的同步保持安静，不发送伪完成状态 | tasks.rs、application.rs；已有离线/条件请求/冲突测试及事件接线 |
| 设置 | backup 的事实来源为库外 backup-settings.json；keys 缺省或混合读取可与偏好/vaultPath 共存。backup 写入独立提交，混写拒绝；vaultPath 仍独立迁移；未知 settings.json 键保留 | application.rs、settings.rs；混合设置及迁移组合用例 |
| 迁移 | 暂停旧索引后复制和校验；新 vault_id 装配 DataService；快照、备份配置/计划和同步 JSON 随私有目录保留。credentialRef 原样引用旧系统凭据，不复制密码；现有外部备份目录不自动删除/改址 | migration.rs、application.rs、team_all.rs |

维护租约只控制本应用。整库备份在发布前再次校对源清单与逐文件哈希，但不能宣称为文件系统快照；外部编辑器仍存在最后检查后的极短竞态。迁移仍为串行本地复制流程，不能由锁外网络操作推断迁移具备后台任务体验。

快照私有 JSON 新增可选 lastUsedMs，用于内容去重后的保留期限；createdMs 保持首次创建时间，说明不被空值覆盖。旧记录回退到 createdMs；公开 VersionEntry 不暴露该内部字段，Rust/TypeScript DTO 不变。旧软件可忽略附加字段，但会按旧 createdMs 清理；回退前需备份私有快照目录，不能承诺旧版执行清理后仍满足新版保留策略。

snapshot_index、sync_state、sync_tombstone、rename_journal 的 SQL 结构与保留策略不变；成员三当前事实来源仍是库外文件，不做无依据双写。links 是派生表，不能拿来存不可恢复业务状态。历史按笔记路径保存；重命名后的完整历史归属迁移仍需单独需求核对，未凭本轮合并宣称完成。

## 失败与环境处理

1. 合并初次编译发现内部方法可见性及 Tauri 退出回调临时借用生命周期问题，修正后继续完整检查。
2. 新组合测试最初用占位旧哈希提交草稿，被 E_STALE_CLIENT 正确拒绝；改用实际 note_read 的哈希，保护断言未降低。
3. 一次旧核心构建缓存出现 rlib/依赖读取错误，使用独立 target 目录、关闭增量并限制并行数重新构建；失败不计通过，依赖与源码回归未跳过。
4. WebDAV 专项最初缺少 Python 包，在项目外独立虚拟环境安装固定 WsgiDAV/Cheroot 后执行；依赖与测试数据未提交。

常规复现入口仍为 scripts/verify.ps1。独立服务专项可显式追加 `-WithWebDavAcceptance -AcceptancePython <已安装验收依赖的Python绝对路径>`；默认验证不会擅自创建系统凭据。环境受限无法运行时如实记录，不标通过。
