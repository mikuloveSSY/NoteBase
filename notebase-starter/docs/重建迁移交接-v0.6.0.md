# 0.6.0 重建、恢复与迁移交接

日期：2026-10-29。成员一迭代。本版接通既有 index_rebuild、settings_get、settings_set，实际接通命令为 11 个、尚未实现 12 个；命令、事件、错误码和数据库表名未新增。settings 仅交付 vaultPath 子集，不能当作其他成员的主题/键位/备份设置已完成。

## 后台重建

`index_rebuild {mode:"full"}` 立即返回 `{jobId}`。重复全量任务或正在进行的索引任务会返回可重试的 E_INDEX_UNAVAILABLE，不重复启动写线程。索引进度仍为 index.progress，完成为 index.state，沿用 0.5.0 的 Tauri 名称映射。

候选库位于当前库外缓存目录的 rebuild-* 临时目录。读取文件并分批写候选，不清空活动数据库；构建后再从真实文件进行全量校对，检查构建期间的本地写入代次，最多追赶三轮。持续变化或非法文件使候选不发布，原库保留，后续增量对账继续处理。中断/切库取消检查和临时目录清理由后台承担。

候选通过校验后 ATTACH，并在一个事务中替换 notes、note_fts、aliases、tags、links 等派生数据，更新版本、构建时间和 index_revision。发布失败回滚旧派生数据；snapshot_index、sync_state、sync_tombstone、rename_journal 四张业务状态表不参与删除。links 当前仍是成员二待接入的派生解析结果，本版候选不重算链接业务，不宣称链接功能完成。

重建期间若旧索引可读，搜索使用它并返回 degraded=true / index_rebuilding。没有可读旧索引时临时扫描文件生成独立查询快照，结果同样标记降级；遇到不可索引文件时原因是 index_rebuilding_partial。扫描页游标绑定文件指纹，文件改变后需重查第一页。每次降级扫描都需枚举/读取真实文件，不承诺大库检索时延；正常查询仍有 0.4.0 的 App 串行锁与独立只读连接限制。

初次打开或版本不匹配也走旁路构建。相同模式但版本值不同会重建派生数据；正常已有索引优先使用并对账，不再每次打开都先清空旧库。

## 损坏与未知模式恢复

`index/recovery.rs` 先取得写会话锁，以只读方式检查身份及可读取的业务状态。身份不匹配、其他写会话或暂时的访问错误不当作损坏覆盖。

实际损坏或未知结构无法按当前模式打开时，原 index.db 和现有 WAL/SHM 移至同目录 recovery-* 归档，随后创建新模式并尝试恢复四张业务状态表的已知字段。完整旧库仍在归档，额外未知表/字段不作猜测性迁移。原业务表无法读取或不符合当前约束时，保留归档并发出明确警告；不能宣称历史状态已全部自动恢复。笔记正文从原 Markdown 文件重建，原文件不改写。

index.recovery-info.json 以临时文件/原子替换保存原件位置与 businessRestored 标志；初始化或恢复失败后，下次打开仍保留警告，避免新空缓存掩盖未恢复的历史状态。UI 显示归档位置。businessRestored 仅表示四张表的已知字段成功恢复，未知扩展仍应核对归档。

恢复归档不自动清理；需要成员二/三或人工在理解原模式后恢复额外状态。直接拷贝坏库、修改 schema_version、删除归档都不是推荐修复方式。物理不可读的数据无法由本版凭空恢复；本版不替代备份。

## 库目录迁移

`settings_get {keys:["vaultPath"]}` 返回 `{values:{vaultPath}}`；空 keys 同样返回本版支持的库路径。`settings_set {values:{vaultPath:"绝对目标路径"}}` 返回 `{ok:true}`。其他键明确拒绝。仅显式调用 settings_set 才复制并切换；普通 vault_open 仍用于打开既有库，不自动复制。

迁移目标必须不存在，父目录必须已存在，源与目标不能相同或嵌套；拒绝符号链接/junction、特殊文件和覆盖已有目标。先列出源清单、汇总大小并检查目标空间，再复制到目标同级临时目录，校验每个相对路径、大小、SHA-256、文件数量和空目录。普通文件、附件、trash 及其他源库文件均复制；源文件在复制期间发生变化会失败，不能仅靠“数量相同”通过。

Windows 使用不带 REPLACE_EXISTING 的 MoveFileExW 发布已验证目录，防止检查后出现同名目标时覆盖。非 Windows 的目录发布返回 E_FORMAT_UNSUPPORTED，尚未作三平台迁移交付。文件修改时间和基本只读属性保留；不声称完整复制 Windows ACL、安全描述符或备用数据流。

库外数据也按新 vault_id 迁移：保留旧缓存目录，校验复制其中快照/草稿/归档等文件，排除活动 index.db/WAL/SHM/写锁和重建/扫描临时目录；四张业务表在只读事务中提取，复制前后核对记录，再写入新 ID 的新数据库。新索引从笔记后台生成。旧库与旧应用数据均保留，不自动删除。

全部复制校验和目标打开成功后才原子更新 settings.json 的 vaultPath，保留其他设置键，并切换当前会话、重新计算库 ID、启动索引。设置提交失败时当前库和原配置保持原状，已验证的新副本可能保留在目标，供核对；不得将这类失败误报为迁移成功。

迁移期间同一 App 的写操作串行阻止，外部变化通过清单/业务记录复核发现；这不是操作系统级文件系统快照，最终核对后的极短竞态与恶意目录替换未完全消除。其他成员的备份/同步暂停接口尚未联调，不承诺与未来并发备份/同步任务无缝迁移。大库复制仍在 IPC 后台派发中串行等待完成，没有取消命令或细粒度复制进度。
