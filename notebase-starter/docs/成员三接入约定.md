## 已有端口与数据边界

- 成员一维护 NoteStore、IndexSession 和 SQL。search_session 返回 Arc，查询可在 App 锁外执行；切库和 App drop 会 cancel。需要暂停的业务必须通过明确协调端口接入，不得持有 App 锁调用需要该锁的回调。
- 成员二维护 NoteService、NoteFiles、NoteStateStore、links.rs。草稿/重命名日志仍用库外 JSON；链接仍从权威文件计算。成员三复用链接分类和消歧，不另行定义一套规则。
- 索引复用 comrak 0.57 的 markdown_options；renderer 的安全 HTML 与索引正文抽取是不同输出，保持同样的语法选项。不要把 Markdown 原文当成安全 HTML 注入预览。
- snapshot_index、sync_state、sync_tombstone、rename_journal 的逻辑值在重建/压缩/迁移中保留；links 是重建派生表，不可放无法恢复的业务状态。数据库路径在库外，不能整体删除来“刷新缓存”。
- 设置更新保留已有 backup、sync 等未知顶层键，但当前设置接口只接受成员四已实现的偏好和单独提交的 vaultPath。保留键不代表已实现成员三设置写入；新增字段校验和迁移须在同一 PR 同步 Rust/TypeScript 与测试。凭据不能放入这些键、日志或浏览器缓存。
- 标签恢复缓存只包含路径，不存正文。成员四的 shell-ui、编辑偏好、窗口与菜单继续独立维护；新增预览/导出/备份面板由成员四接服务，不把全部业务塞进 main.ts。

## 恢复和迁移的接入门槛

当前尚未实现供备份/同步调用的统一维护暂停端口，成员三不得直接并发覆盖活动库。接入备份恢复前，一二三四须共同确定“编辑写入、索引队列、watcher、同步”的拒绝/排队/取消策略和恢复失败的回滚路径。

恢复顺序应为：处理未保存内容与其他窗口 → 阻止新的写入并暂停后台处理 → 创建并确认恢复前快照 → 恢复文件与附件 → 核对路径、数量和哈希 → 重建派生索引 → 重新装配笔记服务并清除旧客户端基准 → 恢复后台服务。任何一步失败均需释放维护状态，保留可回退原件并报错。快照失败不得继续破坏性恢复。

先交渲染与导出，再交快照与备份恢复，最后接同步。每个 PR 明确固定基线、调用样例、错误语义、取消/重试、数据位置和测试。接口变化记录影响及评审结果；本文不预先新增命令或表。

## 接入后必须新增的证据

同一 Markdown 样例在预览/导出/索引中语法一致；缺失和歧义资源有报告；HTML 安全、PDF 中文与分页正确；文件保存与快照结果分别可见；备份可脱离应用还原；恢复前快照失败保护、恢复中断、重启、迁移与多窗口互斥；同步冲突保留双份且凭据不明文落盘。上述均为后续待验收，不计入本轮一二四通过范围。
