# 混合文件夹卡顿修复验收

2026-11-01，起点main 9930456。用户明确报告选中`D:/NoteBase`后软件卡住。本轮只读调查该工程根目录，所有写入/回归使用临时夹具，没有修改用户笔记。

## 复现与原因

3秒/10万项预算的只读os.scandir抽样，在1.626秒访问到90,529个普通文件与9,471个目录，包含29,675个Markdown；达到预算后停止，未扫描完。内容来自工具、仓库和基准目录等。这不是完整目录数量，也不是软件打开/索引性能成绩，不能用于宣称满足十万/二十万笔记性能要求。

原流程在应用锁内完整递归计数，再做私有数据位置校验；关闭及退出回调又在UI线程等待同一应用锁。大量无关资源会延长扫描，关闭操作可能等待该锁而失去响应。旧901624d7交付在快速拒绝回归中等待5秒仍显示准备就绪，未返回；保留old-baseline.txt，不将失败当作通过或宣称已测得永久死锁。

## 修复与接口影响

- 选择目录后，在业务锁及递归扫描前检查当前exe是否位于其中，并检查3个固定的NoteBase工程配置位置（最多读取64KiB、identifier匹配），拒绝软件运行/开发目录及其相应祖先；因此安装在其他位置的exe也能拒绝用户报告的工程根目录。普通包含其他exe、图片、PDF、ZIP的笔记库不受此限制；可使用此前建立的`E:/NoteBase笔记`。
- new_stateful_app在工厂阶段检查既有“私有数据在库外”规则，提前返回无效配置，未改变此规则的含义。
- FsStore逐项读取目录迭代器，非目录/非Markdown项不再额外探测元数据或读正文；根级trash/attachments/.git、链接/目录联接及路径安全规则保留。扫描取消返回E_CANCELLED，不返回半份列表，不删除或整理非Markdown文件。
- 内部Rust NoteStore增加set_scan_cancel默认方法，App提供取消句柄并在请求开始时复位，标准FsStore和后台索引适配器接入。其他成员已有适配器无需增加实现仍能编译；其默认空实现不保证协作取消。此为成员一内部默认端口增量，明确记录Rust定义/调用/测试影响，未新增冻结IPC命令、业务事件、错误码、TS DTO或SQL字段，也未宣称进行了外部团队协商。
- 关闭/退出改为try_lock，主线程不等待长扫描。持锁时通过锁外AtomicBool请求取消；已有长数据任务仍按原安全租约取消，不中断原子写入。若最后窗口已消失，则由后台等待任务安全结束再退出，避免退出回调阻塞或留下无窗口进程。
- 前端显示正在扫描。软件、Cargo/npm/Tauri版本仍为0.7.0开发候选版，依赖不变。
